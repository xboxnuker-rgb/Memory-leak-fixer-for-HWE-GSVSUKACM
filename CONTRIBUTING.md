# Contributing

## Source of truth

Read `README.md`, `AGENTS.md`, and `docs/HANDOVER.md` before changing the patch. Repository documentation and the exact game assemblies are authoritative; old chat excerpts and logs are supporting evidence only.

## Scope

Keep this project focused on the confirmed Schedule I storage-material allocation defect. Worker AI, navigation, storage capacity, shelf packing and general HWE performance changes belong in separate projects unless a reproducible crash proves they share this exact renderer path.

## Local references

Never commit Schedule I, Unity, MelonLoader, generated IL2CPP assemblies, logs, saves, credentials or local SDKs. Point the build scripts at a local MelonLoader installation generated by the matching game version.

## Pull requests

Use a conventional commit and include:

- exact Schedule I, Unity, MelonLoader and backend versions;
- the relevant Harmony target signature;
- build and static-inspection results;
- DLL and package SHA-256 hashes;
- runtime scenarios exercised;
- memory observations over a meaningful soak period;
- known limitations and rollback instructions.

A successful compile is not proof that an IL2CPP Harmony target is safe. Test save initialization, active gameplay, main-menu return, save reload and clean shutdown.
